# EPK-Trainer — тренажёр по моделированию eEPK

Онлайн-тренажёр: студент строит событийную цепочку процесса (Ereignisgesteuerte
Prozesskette) по текстовому описанию задания, а сайт проверяет модель на
соответствие правилам синтаксиса EPK и сверяет её с эталонным решением.

Материал-основа: Saueressig, «Business Process Management: Modellierungsmethoden —
eEPK» (слайды по элементам EPK, операторам, синтаксису, процессным интерфейсам).

## Что умеет

- **8 заданий** по возрастанию сложности: от цепочки «событие → функция → событие»
  до полной eEPK процесса выдачи кредита с параллельными ветвями, XOR-развилками,
  орг. единицами и данными.
- **Редактор на холсте**: перетаскивание элементов, проведение связей за порт,
  режим привязки орг. единиц и документов, зум, автораскладка, отмена, экспорт SVG/PNG.
- **Живая проверка синтаксиса** — замечания пересчитываются при каждом изменении:
  - R1 процесс начинается и заканчивается событием или интерфейсом;
  - R2 строгое чередование Ereignis ↔ Funktion;
  - R3 оператор — это split (1 вход, ≥2 выхода) или join (≥2 входа, 1 выход);
  - R4 орг. единицы и данные привязываются только к функциям;
  - R5 ветви split сводятся join-оператором того же типа;
  - R6 связность модели (нет оторванных фрагментов);
  - R7 нет висячих элементов и дублей связей;
  - R8 у события и функции ровно один вход и один выход;
  - R9 именование: событие — состояние, функция — инфинитив;
  - R10 обратная связь с контрольной функцией.
- **Сверка с эталоном**: сопоставление по типу элемента, названию (с синонимами,
  в т.ч. русскими) и связям. Балл = 45 % элементы + 55 % связи, минус штраф за лишнее.
- **Прогресс** сохраняется в localStorage, задание зачитывается от 85 % при отсутствии
  синтаксических ошибок.
- Вкладка «Правила» — краткая теория с формулировками из материала.

## Запуск

Статический сайт без сборки и без зависимостей:

```bash
python3 -m http.server 8099
# открыть http://127.0.0.1:8099/
```

Модули ES требуют http(s), поэтому открывать `index.html` через `file://` нельзя.

## Тесты

```bash
npm install          # только для тестов (jsdom, esbuild)
npm test             # 40+ проверок ядра и 30+ проверок интерфейса
npm run bundle       # собрать бандл для тестов в /tmp/app.bundle.js
node test/render-preview.mjs   # отрисовать эталоны в preview/*.png
```

- `test/core.test.mjs` — эталоны проходят проверку без ошибок и дают 100 % сами себе;
  типовые ошибки студентов (два события подряд, XOR-split без join, орг. единица
  в контрольном потоке, оператор 1→1, недостижимый фрагмент) ловятся нужным правилом.
- `test/dom.test.mjs` — загрузка страницы, палитра, переименование, проверка,
  переключение заданий, модалка эталона, localStorage, отсутствие JS-ошибок.

## Структура

```
index.html            разметка: панель задания, холст, панель проверки, теория
css/style.css         тёмная тема, адаптив
js/core.js            граф модели, правила R1–R10, сравнение с эталоном, автораскладка
js/tasks.js           банк заданий с эталонными моделями и синонимами названий
js/app.js             холст на SVG, взаимодействие, отрисовка, экспорт
test/                 тесты ядра, тесты интерфейса, рендер превью
```

## Как добавить задание

В `js/tasks.js` добавьте объект в `TASKS`: `text` (немецкий оригинал), `textRu`,
`hints`, `learn` и `reference` — эталонная модель (`nodes` с `id/type/label/alts`,
`edges` с `from/to/kind`, где `kind: 'assoc'` — привязка орг. единицы или данных).
Затем прогоните `npm test`: эталон обязан проходить проверку синтаксиса без ошибок.
